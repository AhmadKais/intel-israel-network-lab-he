## מתכון — מוסיפים VLAN חדש לאתר
🧠 צריך את המתכון הזה פעמיים: ב-P11 (‏VLAN לאלחוט) וב-P22 (מחלקה חדשה בבחינה).

**לפני שמתחילים, בוחרים ורושמים:** את מספר ה-VLAN ‏‎`<V>`‎, את השם שלו ‎`<NAME>`‎, ואת הרשת שלו. ‏‎`<NET>`‎
הוא 3 המספרים הראשונים של הרשת (עבור ‎`10.50.33.0/24`, ‏‎`<NET>`‎ הוא ‎`10.50.33`). הרשת חייבת להיות בתוך
הבלוק של הבניין או האתר. כך לא צריך שום שינוי בניתוב.

**שאר הסימנים:**

<div dir="rtl">

| סימן | פירוש | מאיפה לוקחים |
|---|---|---|
| ‏‎`<TRUNKS>`‎ במתג שכבה 3 | פורטי ה-trunk למתגי ה-access, ובאתר 3 גם הקישור ל-DIST השני. **לא** החברים ב-port-channel: השורה `interface port-channel 1` מכסה אותם | טבלת הכבלים שלכם |
| ‏‎`<TRUNKS>`‎ במתג access | פורטי ה-uplink שלו | טבלת הכבלים שלכם |
| ‎‏‎`<PORTS>`‎ | פורטי משתמשים פנויים במתג ה-access הזה | תוכנית הפורטים שלכם |
| ‎‏‎`<SITE>`‎ | קוד האתר | תוכנית, חלק א |
| ‎‏‎`<DNS>`‎ | כתובת ה-DNS שמופיעה במאגרים האחרים שלכם | תוכנית, חלק ד |
| ‎‏‎`<DHCP-SERVER>`‎ | הכתובת של שרת ה-DHCP של אתר 2 | תוכנית, חלק ד |
| ‎‏‎`<PREFIX>`‎ | 4 הקבוצות הראשונות של ה-‎/64 החדש, כמו ‎`2001:DB8:30:60` | תוכנית, חלק ג |
| ‎‏‎`<V6-POOL>`‎ | השם של מאגר ה-DHCPv6 מסוג stateless משלב 14 | ההגדרות שלכם בשלב 14 |

</div>

### מתכון א — אתר 1 (שלוש שכבות)
👉 **איפה:** ‏DIST1 של הבניין (שרת ה-VTP, והמתג הראשי של ה-VLAN הזה).
```
configure terminal
vlan <V>
 name <NAME>
 exit
interface range <TRUNKS>
 switchport trunk allowed vlan add <V>
interface port-channel 1
 switchport trunk allowed vlan add <V>
 exit
spanning-tree vlan <V> root primary
interface vlan <V>
 description GW <NAME>
 ip address <NET>.2 255.255.255.0
 standby version 2
 standby <V> ip <NET>.1
 standby <V> priority 110
 standby <V> preempt
 no shutdown
 exit
ip dhcp excluded-address <NET>.1 <NET>.10
ip dhcp excluded-address <NET>.131 <NET>.254
ip dhcp pool <SITE>-<NAME>
 network <NET>.0 255.255.255.0
 default-router <NET>.1
 dns-server <DNS>
 end
copy running-config startup-config
```
👉 **איפה:** ‏DIST2. אותו דבר, עם ההבדלים האלה: **בלי** שורות `vlan` ‏(VTP מביא את ה-VLAN), ‏`root secondary`,
כתובת ‎`<NET>.3`, ‏`priority 90`, ורק החרגה אחת: `ip dhcp excluded-address <NET>.1 <NET>.130`.

אחר כך עושים את **"בכל מתג access"** למטה.

👉 **איפה:** שרת ה-DHCP שלכם ‏←‏ **Services** ‏←‏ **DHCP**. ממלאים Pool Name, ‏Default Gateway ‎`<NET>.1`,

### בכל מתג access שיש בו את ה-VLAN הזה (מתכונים א ו-ב)
בוחרים פורטים פנויים. ‏‎`<PORTS>`‎ הוא למשל `fa0/23 - 24`. הם ב"חניה", אז זה גם מעיר אותם.
```
configure terminal
interface range <TRUNKS>
 switchport trunk allowed vlan add <V>
interface range <PORTS>
 description <NAME> users
 switchport mode access
 switchport access vlan <V>
 spanning-tree portfast
 spanning-tree bpduguard enable
 switchport port-security
 switchport port-security maximum 2
 switchport port-security mac-address sticky
 switchport port-security violation restrict
 ip dhcp snooping limit rate 10
 no cdp enable
 no shutdown
 exit
ip dhcp snooping vlan <V>
 end
copy running-config startup-config
```

<div dir="rtl">

> בכוונה אין כאן שורת `vlan`. המתגים האלה הם VTP clients, אז ה-VLAN מגיע לבד משרת ה-VTP. בודקים עם
> `show vlan brief` לפני שמקלידים.

</div>

## ‏P12 — ‏Dynamic ARP Inspection
🧠 **למה:** ההצעה שלכם מבטיחה את זה. ‏DAI זורק תשובות ARP מזויפות (ARP poisoning). הוא בודק כל חבילת
ARP מול טבלת ה-binding של DHCP snooping.

**איפה זה חל:** במתגי ה-access של אתרים 1 ו-2. באתר 3 אין ARP ב-VLANים של המשתמשים (‏IPv6 משתמש
ב-Neighbor Discovery), אז כותבים את זה בספר כסיבה לכך שזה לא שם.

**באילו VLANים:** רק ב-VLANים של מחלקות, כי רק מכשירים עם כתובת DHCP נמצאים בטבלת ה-binding. **לא**
ב-VLAN הניהול או ב-VLAN המדפסות: המכשירים הקבועים שלהם ינותקו.

👣 **שלבים:** קודם עושים את התרגיל בסוף [שלב 06](../steps/06-layer2-security) על הדוגמה. אחר כך:

1. כל מחשב ב-VLANים האלה במתג הזה חייב להשתמש ב-**DHCP**. בודקים:
   ‏`show ip dhcp snooping binding` מראה כל מחשב.
2. 👉 **איפה:** כל מתג access. ‏‎`<DEPT-VLANS>`‎ = ה-VLANים של המחלקות במתג הזה.
   ```
   configure terminal
   ip arp inspection vlan <DEPT-VLANS>
   interface range <TRUNKS>
    ip arp inspection trust
    end
   copy running-config startup-config
   ```

<div dir="rtl">

| ‎# | איפה | מקלידים / עושים | חייבים לראות | אם לא |
|---|---|---|---|---|
| ‎1 | מתג access | ‎‏`show ip arp inspection` | ה-VLANים שלכם מופעלים | שלב 2 |
| ‎2 | מחשב | ‏`ping` לשער שלו | ‏✅ עונה | ה-uplinks לא trusted, או שהמחשב לא בטבלת ה-binding ‏←‏ `ipconfig /renew` |
| ‎3 | אותו מחשב ‏←‏ IP Configuration | ‏**Static**, כתובת פנויה ברשת שלו, ואז `ping` לשער | ‏❌ נכשל — **נכון!** הכתובת לא בטבלת ה-binding | ‏DAI לא פועל ב-VLAN הזה |
| ‎4 | אותו מחשב | חוזרים ל-**DHCP** ‏←‏ `ping` לשער | ‏✅ עונה שוב | עושים שוב, ואז `ipconfig /renew` |

</div>

<div dir="rtl">

> ⚠️ **עושים את ההפעלה מאפס של P26 אחרי זה.** טבלת ה-binding עלולה להיות ריקה אחרי שפותחים את הקובץ
> מחדש. אז המחשבים מאבדים רשת עד `ipconfig /renew`. אם זה קורה, אומרים למורה לפני הבחינה ומסכמים מה לעשות.

</div>

✅ **גמור כש:** כל 4 השורות עוברות במתג אחד, ו-DAI פועל בכל מתג access של אתרים 1 ו-2.

## ‏P13 — ‏EtherChannel בין מתגי הליבה
🧠 **למה:** ההצעה שלכם מבטיחה את זה. בין שני מתגי הליבה יש קישור מנותב אחד. הופכים אותו לצרור של

הצרור הזה הוא **שכבה 3**: יש לו כתובת IP, כמו לפורט מנותב. בדוגמה הקישור הוא Gi1/0/23, אז הצרור משתמש

### ‏P13א — מוסיפים את הכבל השני

### ‏P14ב — נתב הקצה של אתר 1
👉 **איפה:** נתב הקצה של אתר 1.
```
configure terminal
interface tunnel 1
 description GRE to site 3 (encrypted by IPsec)
 ip address <T3-1> 255.255.255.252
 tunnel source gi0/1
 tunnel destination <PUB3>
 exit
ip route <LEGACY> 255.255.255.0 <T3-3>
crypto isakmp key <KEY3> address <PUB3> no-xauth
ip access-list extended S2S-GRE-3
 permit gre host <PUB1> host <PUB3>
 exit
crypto map VPN-MAP 20 ipsec-isakmp
 set peer <PUB3>
 set transform-set S2S-SET
 match address S2S-GRE-3
 end
copy running-config startup-config
```

<div dir="rtl">

> המספר **20** נמצא בין אתר 2 (10) למשתמשים מרחוק (65535). ה-crypto map כבר על Gi0/1, אז לא מחילים

```
 exit
crypto isakmp key <KEY3> address <PUB1> no-xauth
crypto ipsec transform-set S2S-SET esp-aes 256 esp-sha-hmac
ip access-list extended S2S-GRE
 permit gre host <PUB3> host <PUB1>
 exit
crypto map VPN-MAP 10 ipsec-isakmp
 set peer <PUB1>

 match address S2S-GRE
 exit

 end
copy running-config startup-config
```

3. הטכנולוגיות המרכזיות ולמה בחרתם בהן (דקה). פותחים את התצוגה הלוגית.
4. הוכחה חיה אחת: למשל `ping -t` בזמן שמפילים קישור (30 שניות).

## ‏P24 — משימה מעשית: מוצאים את התקלה
🧠 הבוחן שובר משהו ומבקש שתמצאו אותו. שיטה מנצחת ניחושים.

**השיטה.** תמיד בסדר הזה, מלמטה למעלה:
1. **מי לא מגיע לאן?** בודקים בעצמכם. מנסים קפיצה אחת קרוב יותר עד שמשהו עובד.
2. **כבל ופורט:** ‏`show ip interface brief`, ‏`show interfaces status`.
3. **‏VLAN ו-trunk:** ‏`show vlan brief`, ‏`show interfaces trunk`.
4. **כתובת ושער:** ‏`ipconfig /all`, ‏`show standby brief`.
5. **ניתוב:** ‏`show ip route`, ‏`show ip ospf neighbor`, ‏`show ip eigrp neighbors`, ‏`show ip bgp summary`.
6. **מסננים ו-NAT:** ‏`show access-lists`, ‏`show ip nat translations`, ‏`show access-list` ב-ASA.
7. אומרים מה מצאתם **לפני** שמתקנים. מתקנים. בודקים שוב.

**תרגיל.** על `drill.pkt`, חבר לכיתה יוצר תקלה אחת מהטבלה בלי לומר איזו. אתם מוצאים, מתקנים, ומתחלפים.
פותחים מחדש את הקובץ בין תקלה לתקלה.

<div dir="rtl">

| ‎# | התקלה | מה רואים | נמצא עם |
|---|---|---|---|
| ‎1 | פורט משתמש ב-VLAN הלא נכון | המחשב מקבל כתובת של מחלקה אחרת | ‎‏`show vlan brief` |
| ‎2 | ‎‏`switchport trunk allowed vlan remove <V>`‎ | המחשבים של ה-VLAN הזה מקבלים ‎`169.254…`‎ | ‎‏`show interfaces trunk` |
| ‎3 | ‏`no ip dhcp snooping trust` על uplink | המחשבים מקבלים ‎`169.254…`‎ | ‎‏`show ip dhcp snooping` |
| ‎4 | ‏`no standby <V> preempt` במתג הראשי | אחרי תיקון, המתג הראשי נשאר Standby | ‎‏`show standby brief` |
| ‎5 | מפתח OSPF MD5 שגוי בקישור אחד | שכן נעלם | ‎‏`show ip ospf neighbor` |
| ‎6 | ‏`passive-interface` על uplink | שכן נעלם | ‎‏`show ip ospf interface` / ‏`show running-config \| section ospf` |
| ‎7 | ‏`no area <N> range …`‎ ב-ABR | הרבה נתיבים בליבה במקום אחד | ‎‏`show ip route ospf` |
| ‎8 | ‏router-ID שגוי ב-`area … virtual-link` | הבניין הרחוק מנותק | ‎‏`show ip ospf virtual-links` |
| ‎9 | שורה שנמחקה מה-ACL של ה-ASA | המחשב הביתי לא מגיע לאתר שלכם | ‎‏`show access-list` |
| ‎10 | שורת ה-NAT הסטטי נמחקה | אותו סימפטום כמו 9 | ‎‏`show ip nat translations` |
| ‎11 | ‏`neighbor` שגוי של BGP אצל ספק | ה-prefixes של ספק אחד נעלמים | ‎‏`show ip bgp summary` |
| ‎12 | מפתח pre-shared שגוי | ה-VPN נכשל, האינטרנט עדיין עובד | ‎‏`show crypto isakmp sa` |
| ‎13 | ‏MAC שני בפורט של מדפסת | הפורט למטה | ‎‏`show port-security interface fa0/x` |
| ‎14 | שער ברירת מחדל שגוי במאגר DHCP | פינג עובד רק בתוך ה-VLAN | ‏`ipconfig /all`, ואז המאגר |
