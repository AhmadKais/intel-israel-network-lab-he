## מה יהיה לכם בסוף השלב
אפשר לנהל כל מתג בבניין A **מרחוק**, אבל:
- רק עם **SSH** (מוצפן) — אף פעם לא Telnet;
- רק עם **שם משתמש אישי** וסיסמה;
- רק **מרשת הניהול** ‏(VLAN 99) — מחשב במחלקת הנדסה נדחה, גם אם הוא יודע את הסיסמה.

```
 PC-HFA-ADMIN-01 (10.10.19.100, VLAN 99)  ──SSH──►  any switch   ✅
 PC-HFA-ENG-01   (10.10.16.x,  VLAN 10)   ──SSH──►  any switch   ❌ refused by the ACL
```
(מחשב המנהל ב-VLAN 99 ‏←‏ SSH לכל מתג ✅. מחשב של הנדסה ב-VLAN 10 ‏←‏ נדחה על ידי ה-ACL ❌.)

## חלק 1 — קודם מבינים (בשפה פשוטה)

### 1.1 ‏Console לעומת ניהול מרחוק
- **‏Console** = לעמוד ליד המתג עם כבל. בסדר למעבדה, בלתי אפשרי עבור 50 מתגים ב-3 ערים.
- **מרחוק** = להתחבר דרך הרשת מהשולחן של מנהל הרשת. למתג יש 16 "דלתות מרחוק" וירטואליות שנקראות
  **קווי VTY** ‏(`line vty 0 15`) — אחת לכל חיבור מרחוק בו-זמני.

### 1.2 ‏Telnet לעומת SSH

<div dir="rtl">

| | ‎Telnet | ‎SSH |
|---|---|---|
| מוצפן? | ❌ לא — הכול, **כולל הסיסמה**, עובר כטקסט קריא | ✅ כן |
| השוואה | גלויה: כל מי שמחזיק אותה יכול לקרוא | מעטפה סגורה ונעולה |
| להשתמש? | אף פעם | תמיד |

</div>

תראו את ההבדל **בעיניים** במצב Simulation (באתגר).

### 1.3 מה SSH צריך במכשיר Cisco
1. **‏hostname** (לא ברירת המחדל `Switch`) ו**שם דומיין** (`ip domain-name intel.lab`)
   — יחד הם נותנים שם למפתח ההצפנה.
2. **מפתחות RSA** — מפתחות ההצפנה (`crypto key generate rsa`, בגודל **1024**).
3. **שם משתמש** עם סיסמה (`username admin ... secret ...`‎) — ‏SSH מתחבר עם *משתמש*, לא רק
   עם סיסמה.
4. קווי ה-VTY מוגדרים **לקבל רק SSH** ו**לבדוק את שמות המשתמשים המקומיים**.

### 1.4 ‏VLAN הניהול
לכל ציוד הרשת יש כתובת ניהול ב-**VLAN 99** ‏(‎`10.10.19.0/24` בבניין A), בנפרד מהמשתמשים. גם
המחשבים של מנהלי הרשת יושבים ב-VLAN 99 (בהמשך גם מחלקת IT). משתמשים אף פעם לא חולקים VLAN עם
"לוח הבקרה" של הרשת.

### 1.5 ‏ACL — רשימת האורחים לדלתות מרחוק
**‏ACL** ‏(Access Control List — רשימת בקרת גישה) היא רשימה של כללים: *permit* (מותר) או
*deny* (אסור). המתג קורא אותה **מלמעלה למטה** ועוצר ב**התאמה הראשונה**. בסוף כל ACL יש
**"deny לכל השאר"** בלתי נראה.

אנחנו יוצרים ACL **סטנדרטית** (היא בודקת רק את כתובת ה**מקור** — "מי דופק בדלת") ומחברים אותה
לקווי ה-VTY עם `access-class`.

**‏Wildcard masks — הדרך של ACL לכתוב טווח.** זה **ההפך** ממסיכת רשת:
‏‎`0` = "החלק הזה חייב להתאים", ‏‎`255` = "כל דבר מתאים".

<div dir="rtl">

| ‎Wildcard | משמעות | דוגמה |
|---|---|---|
| ‎`0.0.0.0` | בדיוק הכתובת האחת הזו | ‎`10.10.19.100 0.0.0.0` = רק מחשב המנהל |
| ‎`0.0.0.255` | כל ה-‎/24 | ‎`10.10.19.0 0.0.0.255` = ‏10.10.19.0 עד 10.10.19.255 |
| ‎`0.0.255.255` | כל ה-‎/16 | ‎`10.10.0.0 0.0.255.255` = כל חיפה |

</div>

כלל קל עבור ‎/24: **255 פחות כל מספר במסיכת הרשת** ‏←‏ מסיכה 255.255.255.0 ‏←‏ ‏wildcard
‏0.0.0.255.

### 1.6 הגנות נוספות

<div dir="rtl">

| הגדרה | מה היא עושה |
|---|---|
| ‎`login block-for 120 attempts 3 within 60` | ‏3 סיסמאות שגויות תוך 60 שניות ‏←‏ **כל** ההתחברויות נחסמות ל-120 שניות (עוצר רובוטים שמנחשים סיסמאות) |
| ‎`exec-timeout 5 0` | חיבור מרחוק נסגר אחרי 5 דקות בלי פעילות |
| ‎`ip ssh version 2` | רק גרסת ה-SSH החדשה והבטוחה יותר |
| ‎`ip ssh authentication-retries 3` | ‏3 ניסיונות סיסמה לכל חיבור |
| ‎`deny any log` | כל ניסיון שנדחה נרשם ביומן — אפשר לראות מי ניסה |

</div>

## משימה 3 — ‏ACC1: הגדרות SSH, רשימת האורחים, הדלתות מרחוק
👉 **איפה:** ‏ACC1, שורת הפקודה `SW-HFA-A-ACC1(config)#`‎.

### 3א — הגדרות SSH
⌨️ מקלידים:
```
ip ssh version 2
ip ssh time-out 60
ip ssh authentication-retries 3
login block-for 120 attempts 3 within 60
```

<div dir="rtl">

> אם `login block-for ...`‎ נותן ‎`% Invalid input`, דלגו על השורה הזו במתג הזה — כל השאר
> עדיין עובד.

</div>

### 3ב — רשימת האורחים: רק רשת הניהול
⌨️ מקלידים:
```
ip access-list standard MGMT-ONLY
 remark --- who may manage network devices ---
 permit 10.10.19.0 0.0.0.255
 deny any log
 exit
```
✅ אחרי השורה הראשונה שורת הפקודה היא ‎`(config-std-nacl)#`‎; אחרי `exit` — חזרה ל-‎`(config)#`‎.

### 3ג — הדלתות מרחוק: רק SSH, שמות משתמש, רשימת אורחים
⌨️ מקלידים:
```
line vty 0 15
 transport input ssh
 login local
 access-class MGMT-ONLY in
 exec-timeout 5 0
 exit
```

<div dir="rtl">

> **הערה ל-PT:** אם `line vty 0 15` נדחה, הקלידו את אותן ארבע שורות תחת `line vty 0 4`,
> ואז שוב תחת `line vty 5 15`.

</div>

### 3ד — גם ה-console מבקש שם משתמש
⌨️ מקלידים:
```
line console 0
 login local
 end
copy running-config startup-config
```
✅ ‏‎`[OK]`‎.

<div dir="rtl">

> מעכשיו ה-console מבקש **Username: admin** ו-**Password: Intel#Adm1n**. סיסמת ה-console
> הישנה `Intel#Con` כבר לא בשימוש.

</div>

## משימה 4 — בודקים SSH ל-ACC1 לפני שממשיכים

## 🏋 תרגיל — רואים למה Telnet מסוכן ⭐⭐
- 🎯 **המשימה:** ללכוד התחברות Telnet והתחברות SSH במצב Simulation, ולמצוא את הסיסמה.
- 📁 **מתחילים מ:** ה-`step07.pkt` שלכם — קודם **Save As** ‏`step07-telnet.pkt`.
- 👣 **צעדים:**
  1. ב-ACC1 אפשרו Telnet **זמנית**: ‏`configure terminal` ‏←‏ `line vty 0 15` ‏←‏
     ‏`transport input ssh telnet` ‏←‏ `end`.
  2. לחצו **Simulation** ‏←‏ **Show All/None** כדי לבטל את הסינונים ‏←‏ **Edit Filters** ‏←‏ סמנו
     רק **Telnet** ו-**SSH**. סגרו את חלון הסינון (M21).

בבחינה, הבוחן מצביע על הפרויקט **שלכם** ומבקש **להסביר** ו**להראות**. תרגלו כל שאלה

**1. ★1 מהו פרוטוקול SSH? באיזה פרוטוקול מתבצעת ההצפנה? הצג את ההגדרות על גבי המתג או הנתב.**

<details dir="rtl"><summary>תשובה</summary>

‏Secure Shell — ניהול מרחוק בחיבור **מוצפן**, ‏TCP פורט 22 (‏Telnet, פורט 23, הוא טקסט גלוי).
זוג מפתחות RSA ‏(`crypto key generate rsa`) משמש לאימות המכשיר ולהחלפת מפתחות; החיבור עצמו מוצפן
בהצפנה סימטרית (למשל AES). השורות הנדרשות: `hostname`, ‏`ip domain-name`,
‏`crypto key generate rsa`, ‏`ip ssh version 2`, משתמש מקומי, ‏`line vty` ‏←‏ `login local` + `transport input ssh`.

**איפה מראים:** `show ip ssh`, `show running-config` ‏←‏ `line vty`
</details>

**2. ★1 מה ההבדל בין רשימת גישה סטנדרטית לרשימת גישה מורחבת?**

<details dir="rtl"><summary>תשובה</summary>

סטנדרטית (1–99) בודקת רק את כתובת ה-IP של ה**מקור**; ממקמים אותה קרוב ליעד. מורחבת (100–199)
בודקת מקור **וגם** יעד, פרוטוקול ופורט; ממקמים אותה קרוב למקור.

**איפה מראים:** `show access-lists`
</details>

**3. ★1 תראה לי היכן הגדרת רשימת גישה סטנדרטית.**

<details dir="rtl"><summary>תשובה</summary>

ה-ACL של ה-VTY: היא מתירה רק לרשת הניהול / למחשב המנהל לפתוח חיבורי SSH, ומחוברת עם
`access-class <name> in` תחת `line vty`.

**איפה מראים:** `show access-lists`, `show running-config` ‏←‏ `line vty`
</details>

**4. ★1 מהו סדר ההפעלה של רשימות גישה? כיצד נבדוק את פעולת רשימת גישה?**

<details dir="rtl"><summary>תשובה</summary>

מלמעלה למטה; השורה הראשונה שמתאימה מחליטה, והשאר לא נבדקות. בסוף יש **deny any** בלתי נראה.
בודקים עם `show access-lists` — מוני ההתאמות (matches) עולים כשבודקים.

**איפה מראים:** `show access-lists` לפני ואחרי ניסיון SSH
</details>

**5. ◆ למה VLAN ניהול נפרד?**

<details dir="rtl"><summary>תשובה</summary>

תעבורת הניהול (SSH לציוד הרשת) נשמרת בנפרד מהמשתמשים. משתמשים אפילו לא מגיעים לכתובות הניהול של
הציוד, וה-ACL יכולה להתיר רק את רשת המשנה האחת הזו (דרישה 22.5).

**איפה מראים:** `show ip interface brief` ‏←‏ `Vlan99`
</details>
